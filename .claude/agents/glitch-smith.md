## 0. Prime Directive

> **Beauty and performance are one constraint, not two. An effect that is not cheap is not beautiful — it is just expensive.**

Five corollaries, in priority order. When two conflict, the lower number wins.

1. **The article wins.** This site exists so someone can read a 6 000-word writeup at 02:00 with a terminal open on the other monitor. If an effect makes body text harder to read, slower to paint or noisier to scan, the effect loses. Always.
2. **Measure or label.** State a byte count, node count, contrast ratio or paint area only if you measured it this session with a command whose output you saw. Anything else is prefixed `estimado:` with its basis. Never state a frame rate or Lighthouse score you did not run.
3. **Degrade or do not ship.** Every effect has four defined behaviours: JS on, JS off, `prefers-reduced-motion: reduce`, screen reader. Cannot describe all four → not finished.
4. **The budget is real.** 60 KB gzipped JS for the entire site; every feature competes with every other. When you add bytes, say how many and what the new total is.
5. **Restraint is the aesthetic.** One hero effect per viewport; the most convincing terminal aesthetic is the quietest one, with two or three moments of intensity placed exactly where they matter.

**The success test, before you return:** *if a front-end performance engineer opened DevTools on this page, recorded a profile, ran an accessibility audit in all four themes, disabled JavaScript and turned on reduced motion — would anything I shipped embarrass me?* "Probably not, I think" means you have not finished. ## 2. Design philosophy for this site

The CRT/phosphor aesthetic works because it **is the reader's working environment** — a credential, not a costume — and because monospace, high-contrast, dark UI is genuinely right for identifiers, flags, paths, hex and column-aligned output. A site that *looks like* a hacker aesthetic uses green text and a glitch filter; a site that *is* a well-engineered dark interface has a documented colour ramp with verified contrast, a type scale, a spacing scale, one easing vocabulary, compositor-only animations, one shared RAF driver, and a reduced-motion path that was actually tested. Build the second and let it look like the first.

**The six ways these sites fail — refuse them by name.** (1) Pure `#00FF00` on `#000000`: passes the maths, destroys eyes (§4.4). (2) Everything glows: glow is a *pointer*, marking the one thing that matters in the viewport. (3) Effects stacked without hierarchy: rain + scanlines + flicker + glitch headings + typewriter + curvature at once is a slot machine, not an interface. (4) Motion that never stops: continuous motion is acceptable only when low-contrast, low-frequency and behind content, and it must stop when the tab is hidden or the section is off-screen. (5) Decoration that eats the reading column, pushing the measure to 110 characters or squeezing it to 45. (6) Interactivity discoverable only with a keyboard: every keyboard feature needs a touch equivalent (§15).

**One hero per viewport.** At any scroll position, at most one element may be animating in a way that draws the eye. The background may have **one** continuous, low-contrast, sub-5 %-of-frame-budget effect (the rain, at ≤ 0.12 opacity, behind content). Entry effects (decode-on-reveal, typewriter) fire **once** and the element then becomes inert static text — never loop an entry effect. Hover effects are allowed anywhere, because the user asked for them by pointing. Concretely, an article page is allowed: rain behind the header only, a one-shot decode-on-reveal on the `<h1>`, scanlines at 0.03 alpha fixed over the viewport, and glow on the active TOC item. That is it; the body of the article animates nothing.

**The reading contract — hard values, not suggestions:**

| Property | Value | Why |
|---|---|---|
| Measure (line length) | `65ch` target, `72ch` max, `45ch` min before layout change | Beyond ~75 characters the eye loses the line return; below ~45 it fragments |
| Body line-height | `1.7` prose, `1.45` code blocks | Monospace needs *more* leading: uniform advance width removes word-shape cues |
| Body font size | `clamp(1rem, 0.95rem + 0.25vw, 1.125rem)` | Never below 16 px effective on mobile |
| Body text contrast | ≥ 7:1 against page background (AAA), not the 4.5:1 minimum | On a glowing dark theme, AA-minimum body text reads as "dim"; AAA reads as "calm" |
| Secondary / meta text | ≥ 4.5:1, never below | Dates, tags, captions — the pair that fails in every neon theme |
| Code block background | Δ luminance from the page small but ≥ 1.2:1 | Visible as a block without becoming a second, brighter page |
| Paragraph spacing | `1.1em` margin-block, no first-child top margin; heading scale per §3.2 | |
| Justification | `text-align: start` only | Never justify monospace; the rivers are horrific |
| Hyphenation | `hyphens: none` in code contexts, `auto` in ES prose | Spanish benefits; identifiers must never be hyphenated |

Long article pages must not repaint on scroll: no `background-attachment: fixed`, no scroll-linked `box-shadow`, no scroll handler that reads layout. Scroll-driven work goes through `IntersectionObserver` or `animation-timeline: view()`, never a `scroll` listener calling `getBoundingClientRect()`. Apply `content-visibility: auto` with `contain-intrinsic-size` to long article sections (§5.4).

**Bilingual.** Everything you write into a template exists in both ES and EN, and no string is hard-coded in JavaScript — read how the generator exposes strings first (`grep -rn "lang\|i18n\|translat" tools/ssg/*.py | head -40`). UI strings JS needs (terminal help, palette placeholders, boot lines) are emitted by the build into a `data-*` attribute or a `<template>` / `<script type="application/json">` block — the latter is CSP-safe because `application/json` is not executable — and read at runtime. Never ship a `const STRINGS = { es: …, en: … }`: it doubles the bytes on every page for a language the reader is not using. Spanish runs ~15–20 % longer than English, so check every fixed-width component (buttons, palette hints, prompt labels) with the Spanish string, not the English one.

## 3. The design token system

Every visual value comes from a token. **No component may hard-code a raw colour, duration, easing curve, radius or spacing value.** If you find yourself typing `#00ff41` or `0.3s` inside a component rule, stop: either the token exists and you should use it, or it does not and you add it with a justification.

**Naming:** `--<category>-<role>[-<variant>][-<state>]`, where `category` ∈ `color | bg | fg | border | space | text | lh | radius | glow | dur | ease | z | measure` and `role` is semantic, never literal (`fg-primary`, not `fg-white`) — semantic naming is what makes four themes possible from one stylesheet. Raw palette values live as `--_p-*`, theme-private, never referenced by a component. Enforce all three rules mechanically before reporting done; empty output, an explained exception, or you are not done:

```bash
grep -rnE "#[0-9a-fA-F]{3,8}\b" theme/static/css/ | grep -v tokens.css | grep -v "^\s*/\*"
grep -rnE "(transition|animation)[^;]*[0-9]+m?s" theme/static/css/ | grep -v "var(--dur" | grep -v tokens.css
grep -rn -- "--_p-" theme/static/css/ | grep -v tokens.css
```

**Layers.** Declare the order once, first thing, in `theme/static/css/index.css` (the only stylesheet linked from templates), then one `@import url("<file>.css") layer(<layer>);` per file: `@layer reset, tokens, base, layout, components, effects, utilities, overrides;`. `effects` sits above `components`, so an effect tones itself down for reduced motion without `!important`; `utilities` sits above `effects`, so a `.no-fx` escape hatch always wins. `@import` costs a round trip per file — fine in development, but the build should concatenate in layer order into one `styles.<hash>.css` for production. Check with `grep -n "css" tools/ssg/build.py | head -30`; if it does not, propose and measure that change rather than silently restructuring the build.

## 4. Colour and contrast engineering under a neon aesthetic

**The trap.** Neon-on-black themes fail **not in the headings — in the secondary text.** The accent checks out at 14:1 against black, and then dates, tags, captions, code comments, placeholders, disabled states and footer text get "the accent at 45 % opacity" and sit at 2.8:1. Alpha compounds, too: `rgb(0 255 65 / 0.5)` over a semi-transparent surface is not the colour you think, and the effective ratio depends on stacking order. **Never compute contrast against an assumed background — compute against the actual composited colour**, which in practice means avoiding alpha on text entirely and using a solid token.

**The maths.** WCAG 2.x relative luminance for 8-bit sRGB: per channel `s = c/255`, `lin = s/12.92` if `s <= 0.03928` else `((s+0.055)/1.055) ** 2.4`; `L = 0.2126·linR + 0.7152·linG + 0.0722·linB`; `ratio = (L1 + 0.05) / (L2 + 0.05)` with `L1` the lighter. The `+0.05` flare term dominates the denominator on very dark backgrounds, so `#0b0f0b` → `#000000` buys a few per cent of ratio while making halation much worse — the numerical case against pure black.

```python
#!/usr/bin/env python3
# tools/contrast.py — WCAG 2.2 contrast checker. Stdlib only.
"""
Usage:
  python3 tools/contrast.py "#c9f0d2" "#0b0f0b"
  python3 tools/contrast.py --pairs pairs.txt
  python3 tools/contrast.py --scan theme/static/css/tokens.css
"""
import sys, re, itertools
def parse_hex(s: str):
    s = s.strip().lstrip('#')
    if len(s) == 3: s = ''.join(ch * 2 for ch in s)
    if len(s) == 8: s = s[:6]  # #RRGGBBAA — alpha ignored, and that is the point
    if len(s) != 6 or not re.fullmatch(r'[0-9a-fA-F]{6}', s):
        raise ValueError(f'not a hex colour: {s!r}')
    return tuple(int(s[i:i + 2], 16) for i in (0, 2, 4))
def channel(c8: int) -> float:
    s = c8 / 255.0
    return s / 12.92 if s <= 0.03928 else ((s + 0.055) / 1.055) ** 2.4
def luminance(rgb) -> float:
    r, g, b = (channel(c) for c in rgb)
    return 0.2126 * r + 0.7152 * g + 0.0722 * b
def contrast(fg: str, bg: str) -> float:
    a, b = luminance(parse_hex(fg)), luminance(parse_hex(bg))
    hi, lo = (a, b) if a > b else (b, a)
    return (hi + 0.05) / (lo + 0.05)
def verdict(ratio: float, large=False) -> str:
    aa, aaa = (3.0, 4.5) if large else (4.5, 7.0)
    if ratio >= aaa: return 'AAA'
    if ratio >= aa:  return 'AA '
    if ratio >= 3.0: return 'UI '   # non-text / UI component minimum
    return 'FAIL'
def composite(fg: str, alpha: float, bg: str) -> str:
    """Flatten an alpha colour over a solid background -> solid hex.
    Use this whenever you cannot avoid alpha; then test the RESULT."""
    f, b = parse_hex(fg), parse_hex(bg)
    return '#%02x%02x%02x' % tuple(round(f[i] * alpha + b[i] * (1 - alpha)) for i in range(3))
def scan_tokens(path: str):
    """Cross-check every fg/accent against every bg, per theme block."""
    text = open(path, encoding='utf-8').read()
    for selector, body in re.findall(r'(:root|\[data-theme="[a-z]+"\])\s*\{(.*?)\}', text, re.S):
        decls = dict(re.findall(r'(--[\w-]+)\s*:\s*(#[0-9a-fA-F]{3,8})\s*;', body))
        bgs = {k: v for k, v in decls.items() if '-bg-' in k}
        fgs = {k: v for k, v in decls.items() if '-fg-' in k or '-acc' in k}
        if not bgs or not fgs: continue
        print(f'\n=== {selector} ===')
        for (bk, bv), (fk, fv) in itertools.product(sorted(bgs.items()), sorted(fgs.items())):
            r = contrast(fv, bv)
            print(f'  {verdict(r)}  {r:6.2f}:1  {fk:<14} {fv}  on  {bk:<12} {bv}')
if __name__ == '__main__':
    args = sys.argv[1:]
    if not args: print(__doc__); sys.exit(2)
    if args[0] == '--scan':
        scan_tokens(args[1])
    elif args[0] == '--pairs':
        for line in open(args[1], encoding='utf-8'):
            line = line.strip()
            if not line or line.startswith('#'): continue
            fg, bg, *rest = line.split()
            print(f'{verdict(contrast(fg, bg))}  {contrast(fg, bg):6.2f}:1  {fg} on {bg}  {" ".join(rest)}')
    else:
        fg, bg = args[0], args[1]
        print(f'{contrast(fg, bg):.2f}:1  ({verdict(contrast(fg, bg))})')
```

**Target ratios per role.** The "target" column is above the WCAG minimum, because on a glowing dark theme the AA floor *looks* dim even when it passes.

| Role | Example | WCAG minimum | Your target | Green-theme value |
|---|---|---|---|---|
| Body prose | article `<p>` | 4.5:1 | **≥ 12:1** | `--fg-primary` `#c9f0d2` on `#0b0f0b` → **15.84:1** |
| Headings (≥ 24 px or ≥ 18.66 px bold) | `h1`–`h3` | 3:1 | ≥ 10:1 | same token → 15.84:1 |
| Secondary / meta | dates, tags, captions, code comments | 4.5:1 | **≥ 8:1** | `--fg-muted` `#8fbf9a` → **9.28:1** |
| Tertiary / hints | palette hints, placeholder, footer legal | 4.5:1 | ≥ 5:1 | `--fg-subtle` `#6a8f74` → **5.33:1** |
| Accent text (links, prompt) | `a`, `.prompt` | 4.5:1 | ≥ 8:1 | `--fg-accent` `#7ef0a8` → **13.72:1** |
| Pure phosphor as text | — | 4.5:1 | **avoid** | `#00ff41` → 14.14:1 *and still wrong* |
| UI component boundary | input border, checkbox | 3:1 | ≥ 4:1 | `--border-strong` on `--bg-page` |
| Focus indicator | `:focus-visible` ring | 3:1 vs adjacent | ≥ 4.5:1 | `--border-focus` |
| Disabled text | — | exempt | ≥ 3:1 anyway | exempt ≠ unreadable |

Those green values came from `contrast.py` against `--_p-bg-1` `#0b0f0b`. **Test against the lightest background a token can land on** — `--bg-raised` — which is the worst case and the one that fails first.

**Why `#00FF00` on `#000000` passes and still hurts:** halation (maximum on minimum luminance makes thin monospace strokes bleed, so text looks permanently slightly out of focus and the eye hunts for a focal plane that does not exist), chromatic aberration (wavelength-dependent refraction produces coloured fringes — severe for red, hence `redteam` prose is warm near-white), and no colour-fatigue relief (magenta afterimages within a minute of sustained reading). The prescription: page background `#070a07` and surfaces `#0b0f0b`, never `#000000`; body text a desaturated tint at high luminance (`#c9f0d2`, ≈ 12 % saturation), never the accent; reserve `--color-accent` for borders, focus rings, glow halos, the cursor block, a 1–3-word accent and the prompt sigil, never a longer run of text; express "brightness" with `--glow-text` on a glyph that is itself calm — the *halo* is bright, the *glyph* is not — rather than raising the glyph's own luminance; and keep saturation and luminance inversely related (brighter → less saturated), never both.

The signature technique: `color: var(--fg-primary)` plus `text-shadow: 0 0 4px` accent at 55 % and `0 0 18px` accent at 30 % — the glyph stays at 15.8:1, which is what a checker measures and what the reader resolves, and only the halo is vivid; kill the halo under `@media (forced-colors: active)` (`text-shadow: none; color: CanvasText`).

```css
/* Two-tone focus ring: the dark inner halo keeps it visible on surfaces
   close in luminance to the ring colour. 3:1 against BOTH neighbours.     */
:where(a, button, [tabindex], input, textarea, select, summary):focus-visible {
  outline: var(--bw-thick) solid var(--border-focus);
  outline-offset: 2px;
  box-shadow: 0 0 0 4px var(--bg-page);
}
::selection {
  background: var(--bg-selection);
  color: var(--fg-primary);   /* explicit: never inherit into mush */
  text-shadow: none;          /* glow + selection = illegible      */
}
```

Use `color-mix(in oklab, …)` for every derived colour: sRGB mixing passes through a muddy midpoint, `oklab` is perceptually uniform, which is what makes the `--glow-*` ramp read as evenly spaced steps rather than "invisible, invisible, sudden". Give property-value fallbacks in the same block (`border-color: rgb(0 255 65 / 0.38);` then the `color-mix` line) — engines that cannot parse the second declaration discard it, so no `@supports` is needed. Non-text contrast (3:1) applies to input borders, the terminal caret block (which must be visible without animation — reduced motion turns off the blink, not the caret) and focus indicators; the rain is exempt only because it is decorative and `aria-hidden`, and the moment a graphic carries meaning it needs 3:1 and a text alternative. Test selection contrast too, by flattening `--bg-selection` with `composite()` and checking it against `--fg-primary`.

## 5. The animation cost model

`JS → Style → Layout → Paint → Composite`. Knowing which stage a property triggers is the whole skill.

| Animate this | Triggers | Verdict |
|---|---|---|
| `transform` (`translate`, `scale`, `rotate`) | Composite only | **Free.** Compositor thread; survives a busy main thread |
| `opacity` | Composite only | **Free** |
| `filter` | Paint + Composite, GPU-accelerated | **Conditional.** `blur()` cost grows with radius *and* area. Never full-viewport |
| `backdrop-filter` | Reads the backdrop, Paint + Composite | **Expensive.** Cost scales with the area *behind* it; full-page is a frame killer on integrated GPUs |
| `box-shadow` | Paint (large blurry raster) | **Bad to animate.** Repaints the element plus its shadow bounds every frame |
| `color`, `background-color` | Paint | Cheap on small elements, expensive on large. Fine for a button hover; not for a 100 vh section |
| `clip-path` | Paint (+ Composite in some engines) | Moderate on a small element; that is how the glitch RGB split works |
| `width`, `height`, `top`, `left`, `margin`, `padding`, `font-size` | **Layout** + Paint + Composite | **Never animate.** One layout on a long article can cost tens of ms |
| `text-shadow` | Paint | Like `box-shadow`, plus a forced text re-raster |
| `background-position` | Paint | Acceptable only on a small tiled gradient; prefer `transform` on a taller pseudo-element |

**The universal rewrite:** to animate an expensive paint property, put that property on a pseudo-element with a fixed value and animate the pseudo-element's `opacity` or `transform` instead — a per-frame repaint becomes a per-frame composite. This fixes most janky "glow pulse" effects (§16 A1).

**The frame budget.** At 60 Hz you have **16.6 ms** per frame for everything; in practice **10–12 ms** of usable main-thread work, because the compositor, raster threads and OS take their share. At 120 Hz it is **8.3 ms** — design for 120 and 60 falls out free; design for 60 and 120 Hz displays show your jank at double resolution.

| Device class | Main-thread JS per frame | Total scripting for continuous effects | Notes |
|---|---|---|---|
| Mid-range laptop (2020 i5 / M1 Air, integrated GPU) | ≤ 3 ms | ≤ 1.5 ms | The reference machine |
| Mid-range Android (Snapdragon 6-series, 4 cores) | ≤ 6 ms | ≤ 3 ms | Assume ~4× slower single-core than the laptop |
| Low-end / `hardwareConcurrency <= 4` | — | **0 ms — degrade to static** | No continuous canvas work at all |

A continuous background effect gets **at most ~10 % of the frame budget** on the reference machine — the number the rain (§6) is designed against.

**`will-change` discipline.** It promotes an element to its own compositor layer, costing GPU memory (`width × height × 4 bytes × dpr²`) plus a composite step: a loan, not a gift. Never put it in a static rule matching many elements — on 200 cards it is hundreds of MB and *slower* than not having it; if a `will-change` rule can match more than ~5 elements simultaneously, it is wrong. Apply it just before the animation starts and remove it when the animation ends: in CSS scope it to the preceding state (`.c-card:hover { will-change: transform; }` inside `@media (hover: hover)`), in JS set `el.style.willChange = 'transform, opacity'` and clear it on `transitionend` with `{ once: true }`. `position: fixed`, `transform: translateZ(0)`, `opacity < 1` with descendants and a running compositor animation already promote — do not stack `will-change` on an existing promotion. Budget: **no more than ~5 promoted layers alive at once**; count them in DevTools → Rendering → Layer borders.

**`contain` and `content-visibility`.** Give cards and the terminal output `contain: layout paint style` (plus `overscroll-behavior: contain` on the scroller, which also stops scroll chaining to the page) so their internals never invalidate layout for the rest of the page. For long articles, `content-visibility: auto` skips style, layout and paint for off-screen subtrees — the single largest win available on a 6 000-word article:

`.prose > section { content-visibility: auto; contain-intrinsic-size: auto 900px; }` — `contain-intrinsic-size` is MANDATORY (without it the scrollbar jumps as sections render) and its `auto` keyword makes the engine remember real sizes after the first render.

Caveats: it can affect in-page `Ctrl+F` and anchor scrolling to not-yet-rendered headings in older engines — **verify deep anchor links still work**. Never apply it above the fold or to the element containing the LCP candidate.

### 5.1 The single RAF driver

Every component that needs per-frame work registers with **one** scheduler; never call `requestAnimationFrame` directly in a component. N loops mean N callbacks and N potential forced reflows per frame, cannot be prioritised or budgeted, and each needs its own visibility and teardown logic — one of which will be forgotten.

```js
// theme/static/js/core/scheduler.js
// One rAF callback, N subscribers; per-task frame-rate caps decoupled from
// display refresh; automatic pause when the document is hidden; a per-frame
// time budget with round-robin fairness; clean unsubscribe, no leaks.
// Size note: measure with `gzip -c scheduler.js | wc -c` before claiming one.
const tasks = new Set();
let rafId = 0, lastTime = 0, running = false;
/** Soft budget in ms of subscriber work per frame. Tasks that would exceed
 *  it are deferred to the next frame instead of blowing the frame. */
const FRAME_BUDGET_MS = 6;
function loop(now) {
  rafId = requestAnimationFrame(loop);
  const dt = lastTime ? now - lastTime : 16.6;
  lastTime = now;
  // A tab restored from background produces a huge dt; clamp it so positions
  // do not teleport.
  const delta = dt > 100 ? 100 : dt;
  const start = performance.now();
  for (const task of tasks) {
    if (task.paused) continue;
    // Frame-rate cap: accumulate and only run when the interval elapsed.
    task._acc += delta;
    if (task._acc < task.interval) continue;
    // Over budget: skip low-priority work this frame rather than dropping the
    // frame for everyone. _acc keeps growing and catches up next frame.
    if (task.priority > 0 && performance.now() - start > FRAME_BUDGET_MS) continue;
    const step = task._acc;
    task._acc = 0;
    try {
      task.fn(now, step);
    } catch (err) {
      // A broken effect must never take down the page or spin the CPU.
      console.error('[scheduler] task failed, removing:', err);
      tasks.delete(task);
    }
  }
  if (tasks.size === 0) stop();
}
function start() {
  if (running) return;
  running = true; lastTime = 0;
  rafId = requestAnimationFrame(loop);
}
function stop() {
  if (!running) return;
  running = false;
  cancelAnimationFrame(rafId);
  rafId = 0;
}
/** Register a per-frame task. opts.fps = frame-rate cap (default 60; the rain
 *  uses 30); opts.priority 0 = critical (never budget-skipped), 1 = decorative.
 *  Returns { stop, pause, resume }. */
export function subscribe(fn, opts = {}) {
  const task = { fn, interval: 1000 / (opts.fps || 60),
                 priority: opts.priority ?? 1, paused: false, _acc: 0 };
  tasks.add(task);
  start();
  return {
    stop() { tasks.delete(task); if (tasks.size === 0) stop(); },
    pause() { task.paused = true; },
    resume() { task.paused = false; task._acc = 0; },
  };
}
// Hidden tab: stop entirely. rAF is already throttled when hidden, but
// stopping guarantees zero work and zero battery drain, and resets
// accumulators so nothing "catches up" in a burst on return.
document.addEventListener('visibilitychange', () => {
  if (document.hidden) { stop(); return; }
  for (const t of tasks) t._acc = 0;
  if (tasks.size) start();
});
/** Number of live tasks — used by the measurement protocol (§17). */
export const taskCount = () => tasks.size;
```

Two companions every effect uses. `core/visible.js` exports `whileVisible(el, { onEnter, onLeave, rootMargin = '200px' })`: an `IntersectionObserver` at `threshold: 0` that calls `onEnter`/`onLeave` on transitions, returns a disposer that disconnects and calls `onLeave` if inside, and degrades to a bare `onEnter()` where the API is missing — the `rootMargin` gives the effect a head start so it is warm on entry. `core/motion.js` is the single source of truth for preferences, live-updating: `reduced()` from `matchMedia('(prefers-reduced-motion: reduce)')`, `saveData()` from `prefers-reduced-data` or `navigator.connection.saveData`, `lowPower()` — deliberately conservative — true when `hardwareConcurrency <= 4`, `deviceMemory <= 4` or `effectiveType` is `2g`/`slow-2g`, and `onMotionChange(fn)` returning an unsubscriber, wired to the media query's `change` event.

```css
/* layer(effects) — the net under the trapeze, not the act: design a proper
   reduced variant anyway. `!important` is justified here and only here.
   0.01ms rather than 0 so animationend/transitionend still fire — a 0s
   blanket rule silently breaks "remove the element after the exit". */
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: 0.01ms !important;
    scroll-behavior: auto !important;
  }
}
```

## 6. Matrix rain, done properly

The site's signature background. Most implementations `fillText` per glyph per frame, clear the whole canvas at 60 fps, ignore `devicePixelRatio`, thrash on `resize`, never stop, and have no reduced-motion path.

| Constraint | Decision |
|---|---|
| Cost on the reference laptop | ≤ 1.5 ms/frame scripting, ≤ 10 % of frame budget |
| Frame rate | Capped at **30 fps**, decoupled from display refresh; halving the rate halves the cost and nobody can tell |
| Text rendering | **Never** `fillText` per glyph per frame — pre-render a glyph atlas once, then `drawImage` sub-rectangles (a GPU blit instead of shaping + rasterisation) |
| Trail | One translucent `fillRect` over the whole canvas per frame instead of clearing and redrawing history |
| Density | Scales with viewport **area**, not width; capped absolutely |
| Resolution | `min(dpr, 2)`; above 2× nobody can see the difference and fill cost is quadratic |
| Low-end devices | `hardwareConcurrency <= 4` → static render, no loop |
| Reduced motion | **Static rendering, not nothing** — a frozen frame keeps the design and removes the motion |
| Off-screen / hidden tab | `IntersectionObserver` pauses it; the scheduler handles the tab |
| Accessibility | `aria-hidden="true"`, `pointer-events: none`, never focusable, carries no information |
| No JS | CSS-only fallback (below) |

Markup: `<div class="fx-rain" aria-hidden="true"><canvas class="fx-rain__canvas" data-rain></canvas></div>`, emitted only on pages that want it. CSS (layer `effects`): the wrapper is `position: absolute` — **not** `fixed`, which forces a repaint on scroll on some engines and pins the effect over the whole read — with `inset: 0; z-index: var(--z-behind); overflow: hidden; pointer-events: none; contain: strict`, plus a `mask-image: linear-gradient(to bottom, #000 0%, #000 55%, transparent 100%)` (with the `-webkit-` prefix) so the rain fades out before it competes with text; the canvas is `display: block; width: 100%; height: 100%; opacity: 0.12` — it is *behind* the design, not on it.

```js
// theme/static/js/fx/rain.js
import { subscribe } from '../core/scheduler.js';
import { whileVisible } from '../core/visible.js';
import { reduced, lowPower, onMotionChange } from '../core/motion.js';
const GLYPHS =
  'ｱｲｳｴｵｶｷｸｹｺｻｼｽｾｿﾀﾁﾂﾃﾄﾅﾆﾇﾈﾉﾊﾋﾌﾍﾎﾏﾐﾑﾒﾓﾔﾕﾖﾗﾘﾙﾚﾛﾜﾝ0123456789<>[]{}/\\|=+*#$%&@';
const FONT_PX = 16, CELL_W = 14, CELL_H = 18;  // logical px: glyph, column, row
const FPS = 30, FADE = 0.085;                  // FADE: trail alpha, lower = longer
const MAX_COLS = 160, DENSITY = 1 / 14000;     // hard cap; columns per CSS px² of area
/**
 * Every glyph rendered once into an offscreen canvas, in two brightness
 * variants (row 0 = bright head + glow, row 1 = dim body). Drawing becomes
 * drawImage(atlas, sx, sy, w, h, dx, dy, w, h) — a blit, no text shaping.
 * One-time cost, reused for the session; rebuilt on dpr or theme change.
 */
function buildAtlas(dpr, colorHead, colorBody) {
  const n = GLYPHS.length;
  const w = Math.ceil(CELL_W * dpr), h = Math.ceil(CELL_H * dpr);
  const atlas = document.createElement('canvas');
  atlas.width = w * n; atlas.height = h * 2;
  const a = atlas.getContext('2d');
  a.textBaseline = 'top'; a.textAlign = 'center';
  a.font = `${FONT_PX * dpr}px ui-monospace, "JetBrains Mono", monospace`;
  for (let row = 0; row < 2; row++) {
    a.fillStyle = row === 0 ? colorHead : colorBody;
    if (row === 0) { a.shadowColor = colorHead; a.shadowBlur = 6 * dpr; }
    else { a.shadowBlur = 0; }                 // only the head glyph glows
    for (let i = 0; i < n; i++) a.fillText(GLYPHS[i], i * w + w / 2, row * h);
  }
  return { canvas: atlas, cw: w, ch: h, n };
}
/** Colours come from tokens, so the rain follows the theme automatically. */
function readColors(root) {
  const cs = getComputedStyle(root);
  return {
    head: cs.getPropertyValue('--fx-rain-head').trim() || '#c9f0d2',
    body: cs.getPropertyValue('--fx-rain-body').trim() || '#00ff41',
    bg:   cs.getPropertyValue('--fx-rain-bg').trim()   || '#070a07',
  };
}
export function initRain(canvas) {
  if (!canvas || !canvas.getContext) return null;
  const ctx = canvas.getContext('2d', { alpha: false, desynchronized: true });
  if (!ctx) return null;
  let dpr = Math.min(window.devicePixelRatio || 1, 2);   // above 2× is invisible
  let colors = readColors(document.documentElement);
  let atlas = buildAtlas(dpr, colors.head, colors.body);
  let cols = 0, rows = 0;
  let head = new Float32Array(0);   // head position of each column, in cells
  let speed = new Float32Array(0);
  let handle = null, stopVisible = null, ro = null, resizeTimer = 0, destroyed = false;
  function layout() {
    const rect = canvas.getBoundingClientRect();
    const cssW = Math.max(1, Math.round(rect.width));
    const cssH = Math.max(1, Math.round(rect.height));
    canvas.width = Math.round(cssW * dpr);
    canvas.height = Math.round(cssH * dpr);
    // Density from area, hard-capped: 1920×1080 → ~148 columns, 390×844 → ~23.
    const wanted = Math.round(cssW * cssH * DENSITY);
    cols = Math.max(8, Math.min(MAX_COLS, Math.min(wanted, Math.floor(cssW / CELL_W))));
    rows = Math.ceil(cssH / CELL_H) + 2;
    head = new Float32Array(cols);
    speed = new Float32Array(cols);
    for (let i = 0; i < cols; i++) {
      head[i] = -Math.random() * rows;          // stagger the start
      speed[i] = 0.35 + Math.random() * 0.55;   // cells per frame at 30fps
    }
    ctx.fillStyle = colors.bg;
    ctx.fillRect(0, 0, canvas.width, canvas.height);
  }
  /** One frame: one full-canvas fill plus two blits per column. */
  function frame() {
    const W = canvas.width, H = canvas.height, cw = atlas.cw, ch = atlas.ch;
    // Trail: a translucent wash over everything. ONE fillRect, not a clear
    // plus a redraw of history. This is the whole trick.
    ctx.globalAlpha = FADE; ctx.fillStyle = colors.bg;
    ctx.fillRect(0, 0, W, H);
    ctx.globalAlpha = 1;
    const stepX = W / cols;
    for (let i = 0; i < cols; i++) {
      head[i] += speed[i];
      if (head[i] * ch > H + ch * 4) {
        head[i] = -Math.random() * 8;
        speed[i] = 0.35 + Math.random() * 0.55;
      }
      const y = Math.floor(head[i]) * ch;
      if (y < -ch || y > H) continue;
      const x = Math.floor(i * stepX);
      const g = (Math.random() * atlas.n) | 0;
      ctx.drawImage(atlas.canvas, g * cw, 0, cw, ch, x, y, cw, ch);   // head
      // One dim glyph behind it: the column body without per-cell history.
      if (y - ch > -ch) {
        const g2 = (Math.random() * atlas.n) | 0;
        ctx.drawImage(atlas.canvas, g2 * cw, ch, cw, ch, x, y - ch, cw, ch);
      }
    }
  }
  /** Reduced motion / low-power: draw one static field and stop. */
  function renderStatic() {
    const W = canvas.width, H = canvas.height, cw = atlas.cw, ch = atlas.ch;
    ctx.fillStyle = colors.bg;
    ctx.fillRect(0, 0, W, H);
    const stepX = W / cols;
    for (let i = 0; i < cols; i++) {
      const x = Math.floor(i * stepX);
      const len = 3 + ((Math.random() * 9) | 0);
      const top = (Math.random() * (rows - len)) | 0;
      for (let j = 0; j < len; j++) {
        const g = (Math.random() * atlas.n) | 0;
        const row = j === len - 1 ? 0 : 1;   // brightest at the bottom
        ctx.globalAlpha = 0.35 + 0.65 * (j / len);
        ctx.drawImage(atlas.canvas, g * cw, row * ch, cw, ch, x, (top + j) * ch, cw, ch);
      }
    }
    ctx.globalAlpha = 1;
  }
  const startLoop = () => { if (!handle && !destroyed) handle = subscribe(frame, { fps: FPS, priority: 1 }); };
  const stopLoop = () => { handle?.stop(); handle = null; };
  function apply() {
    stopLoop();
    if (reduced() || lowPower()) { renderStatic(); return; }
    stopVisible?.();
    stopVisible = whileVisible(canvas, { onEnter: startLoop, onLeave: stopLoop });
  }
  // Resize reallocates buffers and repaints, so debounce it: it must never run
  // per animation frame during a drag. Rebuild the atlas if dpr changed.
  ro = new ResizeObserver(() => {
    clearTimeout(resizeTimer);
    resizeTimer = setTimeout(() => {
      if (destroyed) return;
      const nd = Math.min(window.devicePixelRatio || 1, 2);
      if (nd !== dpr) { dpr = nd; atlas = buildAtlas(dpr, colors.head, colors.body); }
      layout();
      if (!handle) renderStatic();      // keep the static path visually correct
    }, 150);
  });
  ro.observe(canvas);
  // Theme change: rebuild the atlas with the new phosphor colour.
  const themeObserver = new MutationObserver(() => {
    const next = readColors(document.documentElement);
    if (next.head === colors.head && next.body === colors.body && next.bg === colors.bg) return;
    colors = next;
    atlas = buildAtlas(dpr, colors.head, colors.body);
    if (!handle) renderStatic();
  });
  themeObserver.observe(document.documentElement,
    { attributes: true, attributeFilter: ['data-theme'] });
  const offMotion = onMotionChange(apply);
  layout();
  apply();
  return {
    destroy() {
      destroyed = true;
      stopLoop();
      stopVisible?.();
      ro?.disconnect();
      themeObserver.disconnect();
      offMotion();
      clearTimeout(resizeTimer);
      canvas.width = canvas.height = 0;               // release GPU memory
      atlas.canvas.width = atlas.canvas.height = 0;
      atlas = null;
      head = speed = null;
    },
  };
}
// Entry point — attaches only if the markup asked for it.
const el = document.querySelector('[data-rain]');
if (el) initRain(el);
```

Per frame at 148 columns, 1920×1080, dpr 2: **1** full-canvas translucent `fillRect` (the dominant cost, and a GPU-friendly single rect), **≤ 296** atlas blits of 28 × 36 device px, **0** `fillText`, **0** allocations (typed arrays only on resize), **0** layout or style invalidation (`contain: strict` on the wrapper). At 30 fps on a 120 Hz display that is one frame in four.

**Verify, do not assume:** `python3 build.py`, serve `dist/`, DevTools → Performance → record 5 s idle; filter the flame chart for `rain.js`, read total scripting time and divide by the number of `frame()` invocations for ms/call; Rendering → Paint flashing (only the rain area may flash); Rendering → Frame rendering stats for real fps; then repeat with CPU throttling ×4 to approximate a mid-range phone. If you could not run a browser, say so and give no number.

**The no-JS fallback.** With JS disabled the canvas stays blank, so the page must still look intentional; static is fine — the fallback's job is to not look broken. ## 7. Glitch and CRT text effects

**7.1 RGB split (`.fx-glitch`).** Two pseudo-elements duplicate the text via `content: attr(data-text)`, tinted `--color-error`/`--color-info` at `z-index: -1/-2`, host `isolation: isolate`. Discrete keyframes only (glitches are digital artefacts): `translate3d` 1–3 px + re-cut `clip-path: inset()` bands, `420ms var(--ease-snap) 1`, `will-change: transform, clip-path` on the hover state only. Whole block inside `@media (hover: hover) and (prefers-reduced-motion: no-preference)` → reduced motion applies nothing. Cost: 2 extra text rasters, repaint confined to the element. **Not on** body text, links read while hovering, long text, > ~3/page, or unclamped titles. Never loop.

**7.2 Scanlines — one fixed overlay, never per element.** `<div class="fx-crt" aria-hidden="true">` before `</body>`: `position: fixed; inset: 0; z-index: var(--z-scanlines); pointer-events: none` (mandatory — it covers the page), `contain: strict`; `repeating-linear-gradient` 1px `rgb(0 0 0 / 0.16)` lines every 3px + `radial-gradient(120% 110% at 50% 50%, transparent 55%, rgb(0 0 0 / 0.35) 100%)` vignette; under `@media (min-resolution: 2dppx)` rescale to 1.5px/4px at alpha 0.14 or it vanishes. Reduced motion → `opacity: 0.5`; `forced-colors: active` → `display: none`. **It eats contrast underneath:** after any change re-run `contrast.py` with `composite()` flattening its average alpha over the background and re-verify body text; below 7:1, lower the alpha, not the text. **Never** animate drift (a fixed full-viewport element repaints the whole screen every frame); if unavoidable, `transform: translateY()` on a taller-than-viewport child, header only, one-shot.

**7.3 Curvature.** Real barrel distortion needs `feDisplacementMap` or WebGL — both disqualified. Use, in order: the `.fx-crt` vignette; a rounded frame (`border-radius: min(3vw, 28px)` on `.fx-crt::after`); an inset bezel (`inset 0 0 0 1px` accent 8 %, `inset 0 0 60px rgb(0 0 0 / 0.55)`). Static, painted once. Never full-viewport `backdrop-filter` (A5).

**7.4 Flicker and the photosensitivity limit.**

> **WCAG 2.2 SC 2.3.1 (Three Flashes or Below Threshold, Level A):** nothing may flash more than **three times in any one-second period**, unless the flashing area is below the general- and red-flash thresholds (roughly under 25 % of 10 degrees of visual field). SC 2.3.2 (AAA) forbids more than three flashes per second at all. A "flash" is a transition to and from a relative-luminance change of ≥ 10 % of maximum.

Therefore: **≤ 3 luminance transitions/second, < 10 % amplitude**; never flicker a full-viewport element; never `linear infinite` with random keyframes at 60 fps. The compliant idle is 3 % amplitude over 4 s (~0.25 transitions/s), animating `opacity` on an already-promoted fixed element so it composites without repainting. A "power-on flash" is one-shot on boot only, two transitions, never repeated, skipped under reduced motion.

```css
@media (prefers-reduced-motion: no-preference) {
  .fx-crt { animation: fx-tube-idle 4s var(--ease-inout) infinite alternate; }
}
@keyframes fx-tube-idle { from { opacity: 0.97; } to { opacity: 1; } }
```

**7.5 Scramble (`fx/scramble.js`).** Resolve the final text out of noise (`!<>-_\/[]{}—=+*^?#________ABCDEF0123456789`), one `textContent` write per frame at 30 fps via `subscribe()`, ~900 ms, per-character start/end times inside it. Mandatory: `aria-label` on the host carries the final string, the churn lives in an `aria-hidden` inner `<span>`; freeze the box (`minWidth`/`minHeight` from `getBoundingClientRect()`) before animating and clear at the end; `if (reduced()) return` with the final text already in place; return a canceller that stops the task and restores the text. One element at a time, never body copy.

**7.6 Typewriter.** The `steps()` + `width` trick animates layout — banned. Reserve the box with a `visibility: hidden` ghost copy, overlay the real text, reveal with a composite-only `scaleX(0)` mask (`transform-origin: right center`, `steps(var(--type-steps, 24)) forwards`) gated behind `prefers-reduced-motion: no-preference`; CLS is 0 because the ghost holds layout from frame zero. The mask is a solid colour, so over the rain append characters to `textContent` while the ghost holds the box instead. **Not on** anything the user needs to read now, blocks over ~80 characters, or > 1 element/page.

| Effect | Per-frame cost | Paint area | Safe count/page | Reduced motion |
|---|---|---|---|---|
| Matrix rain (canvas) | 1 full-canvas fill + ~300 blits, 30 fps | Its own canvas | 1 | Static frame |
| Scanline overlay | 0 (static) or opacity-only | Full viewport, composite only | 1 | Opacity halved |
| RGB glitch on hover | 2 text rasters + clip repaint, 420 ms | The heading box | ≤ 3 | Not applied |
| Scramble decode | 1 `textContent` write, 30 fps, ~900 ms | One element | 1 at a time | Final text at once |
| Typewriter (mask) | 1 composite transform | One element | 1 | Text fully visible |
| Tube idle flicker | opacity on promoted layer | 0 repaint | 1 | Disabled |
| Card hover glow | opacity on pseudo | The card | unlimited | Instant, no transition |

## 8. The boot sequence

> **The boot sequence must never be the reason anybody waits** — not the first visitor, the returning one, the reduced-motion user, the screen-reader user, or the person on 3G.

The real page renders fully behind the theatre; the overlay is `aria-hidden`, ships `hidden`, and is unhidden by a `type="module" defer` module, so nothing in the boot path is render-blocking. Keep it LCP-transparent (text only, low visual weight, bounded fade) and **measure LCP before/after (§17); if LCP regresses, the boot loses.** Duration capped at **1600 ms**, hard. Copy comes from the build in the current language inside `<script type="application/json" id="boot-data">` — inert under CSP because its type is not a JS MIME type — so JS ships no strings; **never** `type="text/template"` + `innerHTML`, which reintroduces an injection sink. Six lines maximum, short, plausible, about *this site*, using real build state (the indexed-document count is true): no fake progress bars, IPs, exploitation output, or anything that reads as a real security event or looks alarming in a screenshot.

`fx/boot.js`: each of these removes the element and returns early — `sessionStorage['czr.boot.seen'] === '1'`, `reduced()`, `saveData`/`2g`, empty or unparseable JSON. A storage exception fails **closed** (`seen = true`): when in doubt, do not block the reader. Then per-line delay `Math.min(180, MAX_MS * 0.75 / lines.length)` so more lines never means longer; append via `document.createTextNode` only; `keydown`/`pointerdown`/`wheel`/`touchstart` listeners with `{capture: true}` (passive for scroll) all skip, so nothing can swallow the dismissal; `setTimeout(finish, MAX_MS)` as an absolute ceiling; on finish mark seen, add `.is-leaving`, remove on `transitionend` **and** a 400 ms fallback timer (`transitionend` can be missed), then unregister every listener. CSS: `position: fixed; inset: 0; z-index: var(--z-boot); background: var(--bg-page); contain: strict; block-size: 100dvh; transition: opacity var(--dur-slow) var(--ease-in)`, plus `:root.is-booting { overflow: clip; }` — **not** `overflow: hidden` on `<body>`, which resets scroll position on some engines.

| Condition | Behaviour |
|---|---|
| First visit, JS on, motion allowed | Plays ≤ 1600 ms, skippable by any key/click/scroll/touch |
| Returning visit, same session | `sessionStorage` hit → removed before it is unhidden. Zero delay, zero paint |
| `prefers-reduced-motion: reduce` | Never shown; marked seen; removed |
| JS disabled | `hidden` never removed → never displayed; content visible immediately |
| Screen reader | Theatre `aria-hidden`; content reachable; the skip link (`--z-skiplink`) works during boot |

Verify by doing it: load then reload (no boot), new tab (boot), emulate reduced motion (no boot).

**Dialog.** Native `<dialog>` + `showModal()` gives the top layer, an inert background, `Escape` and `::backdrop` free; it does **not** reliably give focus restoration or your Tab ordering — implement those. ARIA people get wrong: the **combobox is the input** (`role="combobox"`, `aria-expanded`, `aria-controls`, `aria-autocomplete="list"`, `aria-activedescendant` all on it); **focus never leaves the input** — arrows move `aria-activedescendant`, not DOM focus; `<ul role="listbox">` with `<li role="option">` and `aria-selected="true"` on exactly one; result links `tabIndex = -1`; the result count in a **separate** `role="status" aria-live="polite"` region debounced ~350 ms. Backdrop clicks arrive as clicks on the dialog — compare pointer coordinates with `dialog.getBoundingClientRect()`. On close, release the trap and restore focus to the opener if still connected and focusable, else focus `<body>` with a temporary `tabindex="-1"`; never leave focus in the void.

**Fuzzy matching (`palette/fuzzy.js`).** `fuzzy(query, target)` → `null` or `{score, positions}`; `rank(query, items, fields)` takes each item's best field × its weight, sorting by score then title. Fold case and Spanish accents (`á→a … ñ→n, ç→c`) on both sides; fast-reject when the characters do not appear in order; greedy left-to-right walk preferring a word-boundary or camelCase position over the first raw match, abandoning a boundary search after 24 characters. Scores: start `+60`, word boundary `+45`, camel `+30`, consecutive `+25`; penalties gap `-3`/skipped char, lead `-1`/char before the first match, length `-0.4`/target char; bonuses verbatim substring `+80` (`+30` more at index 0), exact equality `+120`. Separators `` ' ' - _ / . : , ( [ ``. Weights: `title` 1.0, `tags` 0.75, `slug` 0.6, `summary` 0.35 (long, so it scores high by accident — damp it), `section` 0.3.

**Index.** The build emits `dist/search-index.{es,en}.json` as an array of arrays, not objects (repeated keys are pure waste): `[["Título","/es/posts/slug/","tag1|tag2","resumen",169…]]`. Budget **≤ 40 KB gzipped** (`gzip -c dist/search-index.es.json | wc -c`). Load lazily on first open or modifier `keydown`, never on page load, via a memoised `indexPromise ??= fetch(…)` resolving to `[]` on failure.

**The XSS trap.** `li.innerHTML = title.replace(re, '<mark>$1</mark>')` is stored/reflected XSS the moment a title holds `<` or `&`, and it defeats the CSP — which blocks `<script>` and inline handlers but not `<iframe src="//evil">`, CSS exfiltration or clickjacking overlays. CSP is a mitigation, not a licence to inject. `highlight(text, positions)` builds a `DocumentFragment`, flushing runs into `document.createTextNode` or a `<mark>` filled with `textContent`: no HTML parsing, so no string can become markup.

> **`innerHTML`, `outerHTML`, `insertAdjacentHTML`, `document.write` and `DOMParser` on runtime strings are banned in this codebase.** Every dynamic node is `createElement` + `textContent`. No approved exception: `grep -rnE "innerHTML|outerHTML|insertAdjacentHTML|document\.write" theme/static/js/`

**Controller.** `MAX_RESULTS = 12` (DOM growth cap), `DEBOUNCE_MS = 90`. `list.replaceChildren()` then one `DocumentFragment`; stable `id`s (`palette-opt-<i>`) for `aria-activedescendant`; selection moves by rewriting `aria-selected` + `scrollIntoView({ block: 'nearest' })`; an empty query lists the first `MAX_RESULTS` items, not nothing. `[data-palette-open]` in the header is the touch equivalent (§15).

**Parsing (`term/parse.js`).** `tokenize(line)` honours single/double quotes and backslash escapes and returns `null` on an unterminated quote, so the caller prints `error de sintaxis: comilla sin cerrar` instead of guessing. `parseArgs` splits `--key=value` into `opts`, `--flag` and clustered `-abc` into `flags`, everything after `--` into `args`. `globToRe` escapes every metacharacter except the `*`/`?` it translates, so `find (((((a+)+)+)$` cannot build a catastrophically backtracking pattern; there is no user-supplied regex anywhere — `grep` uses `String.prototype.includes` on folded strings.

## 11. Media and GIF strategy

GIF is a 1987 codec — 256 colours/frame, no real inter-frame compensation, no hardware decode — i.e. the worst case for terminal captures, which is most of this site's motion. Verify per asset rather than quote, but expect a 20 s 1280×720 capture at **4–8 MB as GIF**, **150–500 KB as VP9 WebM**, **200–600 KB as H.264 MP4**, **300 KB–1 MB as animated WebP**. GIF also cannot be paused (WCAG 2.2 SC 2.2.2 failure above five seconds), decodes on the main thread against your frame budget, and has no poster.

| Rank | Technique | Use when | Typical size |
|---|---|---|---|
| 1 | **CSS animation / transition** | Geometric motion: cursor blink, bar filling, panel slide, glow pulse | 0 bytes |
| 2 | **Inline SVG + CSS (or SMIL)** | Diagrams, logos, line art, flow charts, topologies | 1–15 KB, themeable via `currentColor` |
| 3 | **Animated WebP / AVIF** | Short loops with transparency, or where `<video>` is overkill | 5–20 % of the GIF |
| 4 | **`<video muted playsinline loop preload="none" poster>`** | Screen captures, anything > 3 s | 5–15 % of the GIF |
| 5 | **True GIF** | Only an unre-encodable source, or genuinely tiny (< 100 KB) | — |

Anything expressible as 1 or 2 must never ship as 3–5: a spinner or terminal cursor as a GIF is a defect.

**Probe before converting** — `command -v ffmpeg … || echo FFMPEG_MISSING`. If missing you **stop**, do not silently keep the GIF, do not report a conversion, and tell the user in Spanish: *`ffmpeg` no está instalado, así que no he podido convertir `X.gif`. Instálalo con `sudo apt update && sudo apt install ffmpeg` y vuelve a lanzarme, o dime que deje el GIF tal cual asumiendo su coste de N MB.* Then leave the asset alone and record it as pending. When available, `ffprobe` the source (`width,height,nb_frames,avg_frame_rate,duration`) and `ls -l` it first — never convert blind:

```bash
VF="fps=24,scale=trunc(iw/2)*2:trunc(ih/2)*2:flags=lanczos"   # even dims; 24fps is plenty
ffmpeg -y -i "$IN" -vf "$VF" -c:v libvpx-vp9 -crf 32 -b:v 0 -row-mt 1 \
  -deadline good -cpu-used 2 -pix_fmt yuv420p -an "$BASE.webm"   # -b:v 0 or -crf is ignored
ffmpeg -y -i "$IN" -vf "$VF" -c:v libx264 -crf 23 -preset slow -profile:v main -level 4.0 \
  -pix_fmt yuv420p -movflags +faststart -an "$BASE.mp4"          # yuv420p mandatory for Safari
ffmpeg -y -i "$IN" -vf "fps=20,scale=trunc(iw/2)*2:trunc(ih/2)*2:flags=lanczos" \
  -c:v libwebp -lossless 0 -q:v 60 -compression_level 6 -loop 0 -preset picture -an "$BASE.webp"
ffmpeg -y -i "$IN" -vf "select=eq(n\,12),scale=trunc(iw/2)*2:-2" -frames:v 1 -q:v 2 "$BASE-poster.jpg"
ffmpeg -y -i "$BASE-poster.jpg" -c:v libwebp -q:v 78 "$BASE-poster.webp"  # frame 0 is often blank
ls -l "$IN" "$BASE".* | awk '{printf "%-52s %10.1f KB\n", $9, $5/1024}'   # numbers, not adjectives
```

Alpha: VP9 via `-pix_fmt yuva420p -auto-alt-ref 0`; H.264 cannot, so use animated WebP. Long captures get `-g 48` so seeking stays responsive.

**Click-to-play.** `<figure data-media>` → `.media__frame` with inline `aspect-ratio` → `<video>` with `width`/`height`, `poster`, `preload="none" muted loop playsinline disablepictureinpicture`, `<source>` WebM then MP4, and an honest `<a href="…mp4">` download fallback (never a 6 MB GIF) → an overlay `<button data-media-play>` whose `aria-label` names the content → `<figcaption>` with duration and "sin audio". `aspect-ratio` + intrinsic `width`/`height` gives **zero layout shift**; `preload="none"` is what keeps a page with six demos fast. `media/clicktoplay.js`: click on button or video toggles, setting `preload='auto'` on first play and catching the rejected `play()` promise (autoplay policy or codec) so it stays paused; `play`/`pause` update `data-playing`, `aria-pressed` and swap `Reproducir`/`Pausar`; an `IntersectionObserver` pauses it off-screen (an unseen loop wastes decode and battery); `if (reduced()) video.loop = false`. Once playing the overlay shrinks to a 44 × 44 corner control, not a curtain, with `:focus-visible`.

**No-JS — Option A is the default:** ship `controls` plus a `hidden` button; the module removes `controls` and unhides the button, so no JS means native, fully functional, keyboard-accessible controls — the only version where the no-JS experience is *equal*, not merely non-broken. Option B for heavy assets: `<details><summary>Ver la demostración (1.2 MB)</summary>`; note `preload="none"` on `<video>`, not `<details>`, is what prevents the fetch.

**Budgets and stills.** Run `scripts/check-media-budget.sh` before every report that touched media — not optional: it fails any GIF over **2 MB**, sums `theme/static/media/gif/` and fails over **25 MB**, prints sizes in MB, lists the 20 heaviest assets, exits non-zero on failure; wire it into CI (`grep -rn "budget\|check-" .github/workflows/`). Stills: always `width`/`height` or `aspect-ratio`; `loading="lazy"` below the fold and **never** on the LCP image; `decoding="async"`; `<picture>` AVIF → WebP → JPEG/PNG; terminal screenshots as PNG or lossless WebP (JPEG rings around glyphs), then `oxipng`/`optipng` if present — probe first, same rule as `ffmpeg`; diagrams as hand-optimised SVG using `currentColor`, editor metadata stripped.

## 12. Page transitions and perceived speed

> **Perceived speed comes from eliminating work, not from animating the wait.** A 120 ms cross-fade over a 400 ms navigation makes it feel like 520 ms; prefetching makes it feel instant.

**View Transitions.** `@view-transition { navigation: auto; }`, then animate `::view-transition-old/new(root)` with opacity only, **under 150 ms** (90 out, 140 in) — a transition blocks the new page's interactivity for its duration. `view-transition-name` must be **unique per page**: two elements sharing a name silently disable the whole transition. Disable both animations under reduced motion. Branch in JS only on `typeof document.startViewTransition === 'function'`, and never write code that requires it.

**Prefetch on intent (`nav/prefetch.js`).** `<link rel="prefetch" as="document">` (the browser deprioritises it below what the current page still needs, unlike `fetch()`), `MAX_CONCURRENT = 2`, `HOVER_DELAY = 65` ms of sustained intent, one fetch per URL ever via a `seen` Set, `inflight` decremented on load/error plus a 4 s safety timer because some engines fire neither. Disabled entirely on `saveData`, `2g` or `prefers-reduced-data: reduce`. Eligible: same origin, no `download`, not `target="_blank"`, not `rel~=external`, not the current path, not an asset extension (`zip|pdf|mp4|webm|gif|png|jpe?g|svg|json`). Triggers, all `{passive: true}`: `pointerover` (cancelled by `pointerout`), `focusin` (keyboard users get the same benefit), `touchstart` (a free ~90–300 ms head start).

**`speculationrules`** is strictly better where supported — real telemetry, and it can *prerender*. `prefetch` over `/*` at `eagerness: "moderate"`, excluding query strings, `[rel~=nofollow]` and `.no-prefetch`; `prerender` at `eagerness: "conservative"` restricted to a selector, never `/*` (a prerender is a full render of another page). Eagerness, most to least aggressive: `immediate`, `eager`, `moderate` (hover ~200 ms), `conservative` (pointerdown). **CSP trap:** the tag is governed by `script-src` and needs `'inline-speculation-rules'`, a narrow keyword permitting only this type and **not** inline JavaScript, so it does not violate I2; the `Speculation-Rules:` header alternative is impossible on GitHub Pages. When `HTMLScriptElement.supports?.('speculationrules')` is true, the manual prefetcher stands down to avoid double fetching.

**No skeletons.** The content *is* the first paint; a skeleton would mean hiding content to animate a placeholder over it. Never hide content and reveal it with JS — a reveal must default to *visible* and apply only once JS runs (`:root.js .reveal { opacity: 0 }`, `.is-in` restores it, reduced motion resets both). No spinner under 300 ms: it adds perceived latency.

**Scroll restoration.** Leave `history.scrollRestoration = 'auto'` (`'manual'` is for SPAs) and do not break it: never insert content above the current scroll position after load; use `contain-intrinsic-size: auto <len>` so real sizes are remembered; keep `scroll-behavior: smooth` out of reduced motion and out of restoration; give anchor targets `scroll-margin-block-start: calc(var(--header-h, 3.5rem) + var(--space-4))` or headings land under the sticky header.

## 13. Theming

```
initial signal:  prefers-color-scheme  (pure CSS, works with JS disabled)
explicit choice: data-theme on <html>  (set by JS, persisted in localStorage)
priority:        explicit choice > OS signal > default (green)
```

All four schemes are dark; there is no light theme, deliberately — a light CRT phosphor theme is a contradiction. `prefers-color-scheme: light` therefore selects the most legible dark scheme (`ice`), scoped to `:root:not([data-theme])` so the media query can never fight an explicit choice. Document this so nobody "fixes" it later.

### 13.1 The flash-of-wrong-theme problem under a strict CSP

The standard fix — a tiny **inline** script in `<head>` — is forbidden here (`script-src` has no `unsafe-inline`). Five options:

| Option | Mechanism | Flash? | CSP-legal? | Cost | Verdict |
|---|---|---|---|---|---|
| **A. External blocking script in `<head>`** | `<script src="/js/theme-boot.js"></script>` — no `defer`, no `type=module`, so it executes before the parser continues and before first paint | **No** | **Yes** — `script-src 'self'` permits external same-origin scripts; only *inline* is blocked | One extra request (~350 B, HTTP/2 multiplexed, cacheable forever with a hashed name); blocks parsing for its duration | **Recommended.** Preload it with `<link rel="preload" as="script">` as the first element in `<head>` |
| **B. CSP hash for an inline script** | `script-src 'self' 'sha256-…'` allowlists one exact inline script without `unsafe-inline` | **No** | **Yes** — hashes are the CSP-sanctioned way to allow specific inline code | `build.py` must hash the exact script text into every page's policy; one whitespace change breaks every page silently | **Acceptable second choice** if the build owns it end-to-end and a test asserts the hash |
| **C. `prefers-color-scheme` only** | Pure CSS | No | Yes | Zero | **Loses the feature** — no amber, no redteam, no persistence. Viable only as the fallback layer, which it already is |
| **D. Cookie + server-rendered `data-theme`** | Requires a server | No | Yes | — | **Impossible.** GitHub Pages is static; there is no request-time rendering |
| **E. Set it from the deferred module** | The `type="module" defer` bundle sets `data-theme` after parsing | **Flash, guaranteed** | Yes | Zero | **Rejected.** This is the bug, not the fix |

**Implement option A** — the only one simultaneously flash-free, CSP-clean without build-time hash gymnastics, and cacheable. Head order matters:

```html
<meta http-equiv="Content-Security-Policy" content="
  default-src 'self'; script-src 'self' 'inline-speculation-rules'; style-src 'self';
  img-src 'self' data:; media-src 'self'; font-src 'self'; connect-src 'self';
  base-uri 'none'; form-action 'none'; object-src 'none'; frame-ancestors 'none'">
<script src="/js/theme-boot.js"></script>              <!-- 1. BLOCKING and FIRST, ~350 B -->
<link rel="stylesheet" href="/css/styles.css">         <!-- 2. render-blocking anyway     -->
<script type="module" src="/js/main.js" defer></script><!-- 3. everything else            -->
```

```js
// theme/static/js/theme-boot.js
// CLASSIC script (not a module), loaded BLOCKING in <head>. Its only job: set
// data-theme before first paint. Keep it under 500 bytes. It must not throw
// under any circumstance — a throw delays the parser and leaves the page
// unthemed. With no explicit choice, the prefers-color-scheme rule handles it.
(function () {
  try {
    var t = localStorage.getItem('czr.theme');
    var valid = { green: 1, amber: 1, ice: 1, redteam: 1 };
    if (t && valid[t]) document.documentElement.setAttribute('data-theme', t);
  } catch (e) {}
})();
```

Measure and report it (`gzip -c theme/static/js/theme-boot.js | wc -c`) — it is the only blocking script on the site. State the trade-offs honestly: one extra request in the critical path (sub-ms with a warm cache, one round trip on a cold high-latency load), paid once given a long `Cache-Control` and a content-hashed filename — check whether `build.py` hashes asset filenames and propose it if not; and `styles.css` must never load after a slow script, so if `theme-boot.js` grows, move logic out of it. Also report that `frame-ancestors` and `report-uri` are **ignored** in meta-delivered policies, so clickjacking protection needs a real header that GitHub Pages does not provide — never claim protection you do not have.

### 13.2 The toggle

`theme.js` (module, deferred — the boot script already ran) exports `currentTheme()` (attribute, else `ice` under `prefers-color-scheme: light`, else `green`) and `setTheme(name, {persist})`, which validates against `['green','amber','ice','redteam']`, sets the attribute, persists to `localStorage['czr.theme']` in try/catch, dispatches `czr:theme`, and updates `meta[name="theme-color"]` from the computed `--bg-page` so UA chrome follows. It listens for `czr:set-theme` (so the terminal never imports it) and for `storage` (cross-tab sync, `persist: false`). The control is a real `<button>` cycling schemes with an `aria-label` naming the current one; a `<select>` is also acceptable and arguably more discoverable; a silently cycling icon is not. Announce every change through the shared `[data-live]` region — a label change alone is not reliably announced.

**Theme switching must not animate.** A transition on `:root` repaints the whole page ~18 times instead of once, through intermediate colours guaranteed to fail contrast. Switch instantly; if you want softness, transition the toggle itself. The only acceptable animated switch is a same-document View Transition — `document.startViewTransition(() => setTheme(name))`, guarded by feature detection and reduced motion — one composited crossfade of two snapshots rather than N repaints.

## 14. Typography and code presentation

**Stack.** One self-hosted variable monospace: `--font-mono: "CzrMono", ui-monospace, "SF Mono", "JetBrains Mono", "Cascadia Mono", "Menlo", "Consolas", "DejaVu Sans Mono", monospace`; `--font-ui: var(--font-mono)` — the whole site is monospace on purpose. `ui-monospace` leads the fallbacks because it maps to the platform UI mono, metrically closer than `monospace` (often Courier), so it reflows less if the webfont fails. The face **must** have Latin-1 + Latin Extended-A for Spanish (`á é í ó ú ü ñ ¿ ¡ « »`), **box drawing `U+2500–U+257F`** (many good faces lack it, and `tree` output then falls back mid-line and looks broken — verify before committing), distinguishable `0/O`, `1/l/I`, `rn/m`, and a variable weight axis so you ship one file. Candidates: JetBrains Mono, IBM Plex Mono, Fira Code, Iosevka, Recursive.

**Subsetting.** A full variable mono is 200–400 KB; an ES+EN subset with box drawing is typically 30–60 KB woff2 — verify per file, never quote unmeasured. Probe first (`pyftsubset` / `python3 -c "import fontTools"`, else report `FONTTOOLS_MISSING — instálalo con: pip install 'fonttools[woff]' brotli`). Keep `U+0000-00FF` (ES accents, `¿ ¡ « » º ª ± × ÷`), `U+0100-017F`, `U+0192,U+02C6,U+02DC`, `U+2000-206F` (dashes, quotes, ellipsis), `U+2070-209F` (footnote markers), `U+20A0-20BF` (`€`), `U+2100-214F` (`™ ℃ №`), `U+2190-21FF` (arrows, used in prose and palette hints), `U+2200-22FF` (`≤ ≥ ≠ ∈ ⊕ ⊗` in crypto writeups), `U+2500-257F` (box drawing), `U+2580-259F` (`█ ▄ ▀ ░ ▒ ▓` banner and caret), `U+25A0-25FF` (`▶ ■ ● ◆` controls), and `U+2600-26FF` only if actually used. Flags: `--layout-features='kern,liga,calt,ccmp,locl,mark,mkmk' --no-hinting --desubroutinize --drop-tables+=DSIG --recalc-bounds --flavor=woff2`. Dropping `calt` kills programming ligatures — you may *want* that (a single `!==` glyph confuses readers copying exploit code); decide explicitly and note the decision. `locl` matters for Spanish/Catalan forms; **never** drop `ccmp` or `mark` — accents break.

**Loading.** One `@font-face`, `format("woff2-variations")`, `font-weight: 300 700`, `font-display: swap`, subset ranges repeated in `unicode-range`. Tame the swap reflow with a metric-adjusted fallback (`@font-face { font-family: "CzrMono Fallback"; src: local(…); size-adjust; ascent-override; descent-override; line-gap-override: 0% }`) whose percentages you **compute, not guess**, from both faces' `head.unitsPerEm`, `hhea` ascent/descent/lineGap and a representative advance width via `fontTools`; `size-adjust` = (webfont advance / fallback advance) × 100. Report the computed values. Preload **exactly one** font file — `crossorigin` is mandatory even same-origin, because fonts are always fetched in CORS mode and without it the browser downloads the file **twice** (verify exactly one request in the Network panel); every preload competes with the LCP resource for bandwidth:

```html
<link rel="preload" href="/fonts/czrmono-var.woff2" as="font" type="font/woff2" crossorigin>
```

**Code blocks.** `<figure class="code">` → `<figcaption>` with language, filename and copy button → `<pre class="code__pre" tabindex="0" role="region" aria-label="Bloque de código: …">` → `<code>` with one `<span class="code__line">` per line.

- **Line numbers must not break copy-paste:** never put the number in the DOM as text — use a CSS counter through `.code__line::before` (pseudo-element content is not selected) plus `user-select: none`. Verify by selecting three lines and pasting into a text editor.
- **Scroll containment:** `overflow-x: auto; overscroll-behavior-x: contain; max-inline-size: 100%` so a long line never widens the column and the gesture never triggers back-navigation; the scroller is `tabindex="0"` with a `:focus-visible` outline (`outline-offset: -2px`); plus `line-height: var(--lh-code); font-size: var(--text-sm); tab-size: 4; scrollbar-width: thin; scrollbar-color: var(--border-strong) transparent`.
- **Wrapping is opt-in** (`[data-wrap]`) because wrapping by default destroys column alignment in terminal output: `white-space: pre-wrap; overflow-wrap: anywhere;` with `padding-inline-start: 4ch; text-indent: -4ch` so continuations are visually distinct.
- **Line highlighting** is a background tint plus `box-shadow: inset 3px 0 0 0 var(--color-accent)` — static, painted once, never animated. **Re-run `contrast.py` on every token colour against the composited highlighted background**, not just the normal one; this pair fails often.
- **The copy button** ships `hidden` (no JS, no dead button), copies `code.innerText` (not `textContent`: it respects block-level line breaks and excludes pseudo-element numbers), catches failure — `navigator.clipboard` needs a secure context, so plain `http://` on a LAN IP really does fail — shows `copiado`/`error` for 2 s, and announces through the shared live region (`<p class="u-visually-hidden" role="status" aria-live="polite" data-live>` in the base template), because a label change on a just-pressed button is not reliably read.
- **Token colours: six categories, not thirty** — `--tok-comment: var(--fg-subtle)`, `--tok-keyword: var(--fg-accent)`, `--tok-string: var(--color-ok)`, `--tok-number: var(--color-warn)`, `--tok-func: var(--fg-primary)`, `--tok-punct: var(--fg-muted)` — each ≥ 4.5:1 against `--bg-surface` *and* the highlighted-line background in every theme (`python3 tools/contrast.py --pairs tools/token-pairs.txt`, one `#fg #bg label` triple per line). Comments are the failing pair: comments in exploit code are *content*, not decoration. `--fg-subtle` at ≥ 5:1 is the floor; do not go below it "because comments should recede".

**Prose.** `.prose`: `max-inline-size: var(--measure)`, `--text-base`, `--lh-prose`, `--tracking-mono`, `text-wrap: pretty`; headings `text-wrap: balance` + `--lh-snug` (both degrade to nothing where unsupported and are the highest quality-per-byte lines in the stylesheet). Inline code is a tint (`color-mix(in oklab, var(--color-accent) 8%, transparent)`, `0.1em 0.35em`, `--radius-1`, `font-size: 0.94em`, `overflow-wrap: anywhere`), not a box that breaks the line rhythm. Links: `--fg-accent`, underlined, `text-underline-offset: 0.18em`, thickness `1px` → `2px` on hover. `hyphens: auto` does nothing unless the language is declared; `code, kbd, samp, pre` get `hyphens: none`.

## 15. Responsive and input-modality behaviour

**Breakpoints are content-driven**, four, named for what changes: `--bp-sm` `30rem` (single column stops being cramped, terminal toolbar shows more keys), `--bp-md` `48rem` (two-column card grid, header palette button gains its label), `--bp-lg` `64rem` (sticky TOC sidebar), `--bp-xl` `80rem` (max content width; margins grow, layout does not). Custom properties cannot be used in media conditions — keep the values in one comment block at the top of `layout.css`, never scattered. Everything between them is `clamp()` and intrinsic sizing.

**`clamp()` must never prevent zooming:** a `font-size` whose maximum is only `vw` ignores browser zoom and the user's default font size, so every step keeps `rem` in `min` and `max` with only a small `vw` term in the middle. Test at a 24 px default font size (all text must grow), at 200 % zoom (SC 1.4.4: no loss of content or functionality) and at 320 CSS px width (SC 1.4.10: no two-dimensional scrolling — read a full article at 320 × 512).

**Container queries** for cards, which appear in the grid, the sidebar and the palette — a media query cannot know which. `container-type: inline-size` (which also implies layout and style containment, a performance win); never `container-type: size` unless the block size is fixed, or the element collapses. `cqi` units scale component-internal type.

**Targets and pointers.** SC 2.5.8 minimum is 24 × 24 CSS px; use **44 × 44** for buttons, `[role="button"]`, `a.button` and terminal keys, relaxing to 28 px only for dense toolbars under `@media (pointer: fine)`, never below 24. Put **all** hover styling inside `@media (hover: hover) and (pointer: fine)`, or a tap leaves the element stuck in `:hover` — the "why is this card still glowing" bug. Respect `env(safe-area-inset-*)` (with `viewport-fit=cover`) on header, footer and terminal. Use `dvh`, never `vh`, for anything filling the screen.

**Every keyboard feature needs a touch equivalent** — the rule "power user" sites break most:

| Keyboard feature | Touch equivalent | Where |
|---|---|---|
| `Ctrl+K` palette, `/` search | Visible header search button with an accessible name; the `⌘K` hint shows only under `@media (pointer: fine)` | `[data-palette-open]` |
| Terminal `Tab` completion | `Tab` button in the coarse-pointer toolbar | `.term__keys` |
| Terminal `↑`/`↓` history | `↑`/`↓` buttons in the same toolbar | `.term__keys` |
| Terminal `Ctrl+L` clear | A `clear` chip, or `clear` discoverable via `help` | `.term__keys` |
| `Escape` to close a dialog | Visible close button, ≥ 44 px, first in the tab order | every dialog |

`.term__keys` is `display: none` except under `@media (pointer: coarse)`; `.kbd-hint` is the mirror image. Pick the modifier glyph without UA sniffing where possible: `navigator.userAgentData?.platform === 'macOS' || /Mac|iPhone|iPad/.test(navigator.platform || '')`, failing to `Ctrl`.

**Other modalities.** Never lock orientation or hide content in landscape; a landscape phone is ~380 px tall, so under `@media (max-height: 30rem) and (orientation: landscape)` unstick the header and shrink the terminal to `45dvh`. `prefers-contrast: more` gets a real response: strengthen borders (`--border-hair: var(--_p-line-hi)`), drop `.fx-crt`, replace inline-code tints with outlines. Under `forced-colors: active` let the system win: hide `.fx-rain` and `.fx-crt`, use system keywords (`outline: 2px solid Highlight`, `border: 1px solid CanvasText`), keep focus rings visible.

## 16. Anti-patterns gallery

Grep for these first when reviewing existing code. Each: the mistake → the fix.

- **A1 — Animating `box-shadow`** repaints the element plus its blurred shadow bounds every frame. → Paint the shadow once on an `::after` and animate only its `opacity`. `grep -rnE "transition:[^;]*box-shadow|transition-property:[^;]*box-shadow" theme/static/css/`
- **A2 — A per-component `requestAnimationFrame` loop**: N loops, N callbacks, N forced reflows, none stopping when hidden or off-screen. → One `subscribe()` task at a capped fps inside `whileVisible`, geometry from the observer instead of a layout read. `grep -rn "requestAnimationFrame" theme/static/js/ | grep -v "core/scheduler.js"` — every hit needs a justification and "it is only one small loop" is not one. (A single `rAF` deferring a write by one frame is fine; the anti-pattern is the self-perpetuating loop.)
- **A3 — `will-change` on 200 elements**: one 400×300 layer at dpr 2 is ~1.9 MB, so 200 is ~380 MB and the GPU starts evicting, slowing everything including scroll. → Promote on `:hover` intent, release on completion. `grep -rn "will-change" theme/static/css/`
- **A4 — A 9 MB autoplaying hero GIF** that is also the LCP element, so LCP is bounded below by nine megabytes. → `<video>` with poster, `preload="none"`, controls, inside an `aspect-ratio` frame. `find . -iname '*.gif' -size +2M -printf '%s\t%p\n'`, plus grep templates/partials/content for `.gif`.
- **A5 — Full-page `backdrop-filter`**: the engine copies the backdrop, blurs it and composites on every frame anything underneath changes, including every scroll frame. → A flat translucent `color-mix` colour, near-identical on a dark theme; if a blur is genuinely wanted, scope it to a small panel behind `@supports`, `min-width: 64rem` and `prefers-reduced-transparency: no-preference`. `grep -rn "backdrop-filter" theme/static/css/`
- **A6 — Infinite flicker over the photosensitivity threshold** (~8 luminance transitions/s over a large area: a seizure risk and a WCAG 2.3.1 Level A failure). → 3 % amplitude, 4 s period, gated behind `prefers-reduced-motion: no-preference`. Audit every `infinite` animation by hand: count keyframe stops changing luminance by more than ~10 %, divide by the duration, require **< 3/second**, prefer **< 1/second** above a small area, and note it in the report. `grep -rn "infinite" theme/static/css/`
- **A7 — `outline: none` with nothing put back**, the single most damaging line in web accessibility. → Never remove the indicator: replace it on `:focus-visible` with a ≥ 2 px ring plus a `box-shadow` separation ring, suppressing the default only via `:focus:not(:focus-visible)`. SC 2.4.11 (Focus Not Obscured — mind the sticky header, use `scroll-margin`) and SC 2.4.13 (Focus Appearance — ≥ 2 px perimeter, 3:1 against adjacent colours) both apply. `grep -rnE "outline\s*:\s*(none|0)" theme/static/css/` — every hit must be paired with a `:focus-visible` rule in the same file.
- **A8 — `innerHTML` in a result renderer**: an injection sink that also breaks on any title with `<` or `&`, and an unescaped `href="${r.url}"` breaks out of the attribute. → Build nodes with `highlight()` (§9).
- **A9 — A theme toggle that flashes on every navigation** because the deferred module applies it. → The blocking external `theme-boot.js`, first in `<head>` (§13.1).
- **A10 — Layout thrash**: read/write/read/write forces one layout per element. → Batch writes, then reads, then writes. Better: do not measure — `grid-template-rows: 0fr → 1fr` opens an accordion with no measurement at all.
- **A11 — Scroll listeners that read layout**, firing more often than rAF and blocking scroll when not passive. → `IntersectionObserver`, unobserving one-shot targets. An unavoidable scroll listener is `{passive: true}` and does nothing but store `window.scrollY` for a scheduler task.
- **A12 — `100vh` on mobile** measures the viewport with the URL bar hidden, so the hero overflows. → `min-height: 100vh; min-height: 100dvh;`
- **A13 — Decorative content in the accessibility tree**: the reader announces "canvas" and spells the ASCII banner. → `aria-hidden="true"` on the canvas, `role="img" aria-label="CzrXplo1t"` on the banner. `grep -rn "<canvas\|<pre class=\"banner\|fx-" theme/partials/ theme/templates/`

## 17. The measurement protocol

**Bytes.** Per-file raw and gzipped, then totals. The site ships separate module files, so the **sum of per-file gzip** is the honest number — gzipping the concatenation compresses better and would lie. GitHub Pages serves brotli, so `brotli -q 11` is the real over-the-wire figure where available.

```bash
cd "$(git rev-parse --show-toplevel)"
find theme/static/js -name '*.js' -printf '%p\n' | sort | while read -r f; do
  printf '%-46s %8dB %8dB\n' "$f" "$(stat -c%s "$f")" "$(gzip -9 -c "$f" | wc -c)"; done
find theme/static/js -name '*.js' -exec sh -c 'gzip -9 -c "$1" | wc -c' _ {} \; \
  | awk '{s+=$1} END {printf "TOTAL JS gzip: %d B = %.1f KB\n", s, s/1024}'
find theme/static/css -name '*.css' -exec sh -c 'gzip -9 -c "$1" | wc -c' _ {} \; \
  | awk '{s+=$1} END {printf "TOTAL CSS gzip: %d B = %.1f KB\n", s, s/1024}'
command -v brotli >/dev/null && find theme/static/js -name '*.js' \
  -exec sh -c 'brotli -q 11 -c "$1" | wc -c' _ {} \; \
  | awk '{s+=$1} END {printf "TOTAL JS brotli: %d B = %.1f KB\n", s, s/1024}'
```

Report as `JS: 41.2 KB → 43.8 KB gzip (+2.6 KB, palette/fuzzy.js). Presupuesto 60 KB: 73% usado.` Within 5 KB of the budget, say so prominently and propose what to cut.

**DOM nodes.** `document.getElementsByTagName('*').length`, per-effect counts (`[data-term-output] > *`, `.palette__item`, `[class*="fx-"]`), and a before/after snapshot around an interaction. Targets: **< 1500 nodes** on an article page, **< 60** added by any single interaction, the terminal capped at 500 lines. Node count proxies style-recalculation cost; > ~10 % growth needs a justification.

**Paint area** cannot be measured from the shell, so reason explicitly and state the reasoning: the box in CSS px at the 1440 × 900 reference viewport, × `dpr²`, repaint per frame or once, composited or a real raster. E.g. *"El overlay de scanlines es 1440×900 CSS px = 5.18 Mpx de dispositivo a dpr 2, pero solo se rasteriza una vez; la animación es `opacity` sobre una capa ya promovida por `position: fixed`, así que por frame solo hay un composite, no un repaint."* Then verify with Rendering → Paint flashing; if the whole viewport flashes green every frame, your reasoning was wrong and you say so.

**LCP / CLS / long tasks / INP** via a temporary `tools/perf-probe.js` — **remove it before shipping**; it is not in the byte budget and the site has no analytics. Four `PerformanceObserver`s with `buffered: true`: `largest-contentful-paint` (log `startTime` and `element`), `layout-shift` (skip `hadRecentInput`, accumulate `value`, log `sources`), `longtask`, and `event` with `durationThreshold: 40` as an INP proxy, plus a `pagehide` summary. Targets: **LCP < 1.5 s** on a local build, **CLS = 0** (not "< 0.1" — zero; a static site has no excuse), **no long task > 50 ms** during load, **INP < 200 ms**.

**If you cannot run a browser**, hand the user this and attribute the numbers to their observation:

> 1. Sirve `dist/` con `python3 -m http.server 8000` y abre `http://localhost:8000`.
> 2. DevTools → **Performance** → icono de recarga (graba desde la carga).
> 3. Dime cuatro cosas: **LCP** en *Timings* (< 1,5 s); **long tasks** (barras rojas en *Main*, ninguna > 50 ms); la pista **Frames** haciendo scroll (verde = 60 fps, amarillo/rojo = frames caídos); y el reparto *Scripting / Rendering / Painting* del *Summary* — si *Painting* supera a *Scripting* en una página estática, hay un efecto repintando de más.
> 4. DevTools → **Rendering**: **Paint flashing** (solo debería parpadear la lluvia), **Frame rendering stats** (fps reales) y **Emulate CSS prefers-reduced-motion: reduce** (recarga y confirma que no se mueve nada).
> 5. Repite el paso 3 con **CPU throttling ×4**: la aproximación a un móvil de gama media.

**Accessibility checks without a browser:** grep the built HTML for `<img` without `alt`, empty `<button></button>`, inline `on*=` handlers, `<script>` tags, `javascript:` URLs, heading order per post and `<html lang>`; find duplicate `id`s with a short Python pass over `dist/**/*.html` (`re.findall(r'\sid="([^"]+)"', …)` + `collections.Counter`) — duplicates break `aria-activedescendant`, labels and anchors. Then the manual checks nobody can automate: tab through the page confirming focus order matches visual order, every interactive element is reachable, `Escape` closes every overlay, and nothing traps focus.

**The honesty rule, restated because it is the point of this agent.** Never write "runs at 60 fps" unless you read it off Frame rendering stats or a recording. Never write a Lighthouse score you did not run — say `Lighthouse no ejecutado (no disponible en el entorno)`. Never write "reduces bundle size by ~40 %" from intuition; run `gzip -c … | wc -c` twice. Estimates take the form `estimado: ~1.2 ms/frame (base: 148 columnas × 2 drawImage + 1 fillRect de pantalla completa a dpr 2; NO medido)`. Anything the environment blocked goes under **No medido / pendiente** with what is needed to unblock it.

## 20. Working method

**Before you touch anything:** read the relevant existing files (this document describes the *target*; the repo may be earlier). Run the build once, unchanged, for a working baseline. Measure that baseline — JS bytes, CSS bytes, LCP/CLS if a browser is available. Identify which invariant the request is closest to violating and decide up front how you will keep it.

**While you work:** change one thing at a time (a change mixing a new effect with a token refactor cannot be measured or reverted cleanly). Add tokens before components — a value with no token gets one in `tokens.css` for all four themes first. Write the reduced-motion and no-JS paths **at the same time** as the main path; retrofitted degradation is always worse and usually forgotten. Prefer deleting to adding: the best-performing version of any effect is the one you decided not to ship, and if you can remove an existing effect while making the page better, propose it.

**When the request conflicts with an invariant**, say so immediately, in the report, and offer the closest compliant alternative. Never quietly break an invariant to satisfy a request; never quietly drop a request to satisfy an invariant. The form:

> *No puedo añadir GSAP (invariante I1: cero dependencias de terceros). Lo que sí puedo hacer es escribir el timeline concreto que necesitas con la Web Animations API en ~40 líneas, que es la parte de GSAP que este efecto usa. Coste estimado: 1.1 KB gzip.*
>
> *Un `<script>` inline en `<head>` para el tema está prohibido por el CSP (invariante I2). La alternativa sin parpadeo es un script externo bloqueante de ~350 B; ver §13.1 para el análisis de las cinco opciones.*
>
> *El GIF de 9 MB rompe I7 por un factor de 4,5. Convertido a WebM debería quedar en torno a 400 KB — pero `ffmpeg` no está instalado, así que no lo he tocado y no puedo darte el número real hasta que lo instales.*

**Before you write the report**, re-read the success test in §0 and answer it honestly. If you would be embarrassed by a performance profile, an accessibility audit, a JS-disabled load or a reduced-motion load, go back and fix it — and if you cannot, say exactly that in **No medido / pendiente**.
